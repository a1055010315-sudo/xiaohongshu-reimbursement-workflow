# 批次归档与展示规则

阶段 B 制作或验证文字说明、本次明细、截图归档及“报销明细对应截图表”时完整读取本页。批次状态、两道门禁、临时目录和发布以父级 `SKILL.md` 为准。

## 目录

1. 唯一数据源与类目
2. 最终归档结构
3. 摘要预览与门禁绑定
4. 本次报销明细
5. 原图归档
6. 对应截图表
7. 一次展示与视觉验收

## 1. 唯一数据源与类目

使用当前任务的 `batch-manifest.json` 中同一组规范化交易驱动全部产物；摘要、明细、截图表和候选校验不得分别重新解析材料。

- 目标总表类目默认 `小红书报销`。除非用户明确指定其他类目，记录均归入目标类目。
- `公司报销` 等非目标类目只进入文字说明、原图归档和对应截图表，不进入目标类目的本次明细、候选总表或根表。
- 每笔记录只能有一个报销类目；一张凭证可以通过多对多证据关系覆盖多笔或多个类目。
- 用户写出具体单子或项目名时，备注使用该稳定名称；不要改成泛化的 `日常报销`。

## 2. 最终归档结构

归档文件夹最终只保留下列交付物：

```text
<时间段>_小红书报销/
├─ <时间段>_报销文字说明.txt
├─ <时间段>_本次报销明细.xlsx
├─ <时间段>_报销明细对应截图表.xlsx
├─ 小红书支出总表_截至<结束日期>.xlsx
└─ 报销截图/
   ├─ 小红书报销/
   ├─ 公司报销/
   └─ <其他实际出现的报销类目>/
```

不要留下 manifest、验收证书、截图与款项说明、截图对应关系 TXT、差异说明、聊天区间辅助目录、预览、日志、解析文件、构建脚本或失效修正版。

## 3. 摘要预览与门禁绑定

将已核对记录写为结构化 JSON，使用 `scripts/build_reimbursement_summary.mjs`，禁止手工拼接：

```text
node scripts/build_reimbursement_summary.mjs --input <input.json> --preview
node scripts/build_reimbursement_summary.mjs --input <input.json> --output <new-output.txt> --expect-sha256 <预览textSha256>
```

预览模式输出确定性的 `summary` 完整正文、`textSha256` 和金额摘要，不创建文件。阶段 B 直接把完整正文贴在对话中；不要等待单独的自然语言确认。第一道精确门禁同时确认该摘要和其余业务核对包。收到第一道门禁后才把预览哈希作为 `--expect-sha256` 写最终 TXT；输入变化或哈希不一致时必须在创建文件前失败。

输入使用 `targetCategory` 指定目标类目；每个 `entry` 使用 `category`、字符串金额 `amount`、标签 `label` 和布尔值 `reimbursable`。可用 `expectedFeeTotal`、`expectedRealTotal` 和 `expectedCategoryTotals` 独立验算。

格式要求：

- 每个报销类目单独成段；目标类目在最前，其余按材料首次出现顺序。
- 标题为 `<完整中文时间段><报销类目>`，例如 `2026年7月1日-7月13日公司报销`。
- 同一人员需实报的多笔合并一行；每个对公不实报对象单独汇总一行。段内不写项目、逐笔日期、备注、截图引用、路径或 SHA256。
- 标签和金额之间使用全角冒号 `：`；金额最多三位小数，保留有效精度，不加千位分隔符。
- 目标类目始终输出 `实报合计`；存在 `对公已付不实报` 时，在其前输出包含目标类目全部支出的 `费用合计`。
- `费用合计` 不含非目标类目；`实报合计` 还要排除目标类目的 `对公已付不实报`。
- 每个非目标类目列人员/分类汇总后输出独立 `合计`；它只表示文字记录，不表示已进入目标总表。
- 时间段写完整中文日期并带年份；跨年时两端都写年份。
- 原义、人员或分类不明确时先确认，不得为凑平总额改写。

## 4. 本次报销明细

本次明细只包含当前时间段、目标总表类目的本批交易；不得包含历史记录或非目标类目。优先沿用基准总表的视觉语言和实际列语义。常见 A-F 为：

| 列 | 内容 |
|---|---|
| A | 日期 |
| B | 项目或费用明细 |
| C | 单笔金额 |
| D | 费用组合计 |
| E | 支出人 |
| F | 备注或分类；`对公已付不实报` 必须明确标记 |

基线不是 A-F 时按 Excel reference 识别实际列语义；不能可靠映射就询问。为完整显示三位小数或长文字可以做最小列宽调整，但不得另换配色、字体、边框或布局。

## 5. 原图归档

在 `报销截图` 下为每个实际出现的类目建立同名文件夹。`公司报销` 必须单独进入 `报销截图/公司报销`。

- 复制原始文件内容和扩展名；重名时加稳定编号，不覆盖、不裁剪、不压缩，不用 OCR 文本替代。
- 一张图覆盖多个类目时，每个相关类目各保留一份原图副本，并在 manifest 标记共享来源。
- 每个归档副本都与已登记的来源 SHA256 比较；来源本就在正确目标位置时不重复复制。

## 6. 对应截图表

对话版和本地 `.xlsx` 必须使用同一组逐笔记录、备注和图片顺序。

- “页”只指可见 Sheet，不是打印页或 PDF 页。目标类目固定为 Sheet1；有 `公司报销` 时固定为 Sheet2；其他实际出现的非目标类目按首次出现顺序追加可见 Sheet。
- 不得为 manifest、审计或调试增加隐藏 Sheet；内部检查点留在任务临时目录。
- 每个 Sheet 使用 `日期｜支出人/主体｜项目｜金额｜备注｜图1｜图2｜…`。列名必须是 `备注`，它放在全部图片列之前。
- 每张图单独占一个 `图N` 列，同一单元格不得纵向堆叠多图。直接付款/业务凭证在前，财务文字说明或拆分依据在后；没有图片的后续列留空。
- 图片必须嵌入，不得用外链、文件名或路径代替。保持宽高比和内边距，设置足够列宽/行高，确保图片、金额和备注无裁切、遮挡或跨行。
- 同一凭证覆盖多笔时可在相关业务行放置独立锚点；图片哈希相同不能成为删除业务行的理由。实现支持时复用同一 OOXML media part，避免重复写入相同图片字节。

## 7. 一次展示与视觉验收

阶段 A 只给疑点附图。对应截图表完成语义和视觉验收后，在对话中完整展示一次；所有分批合起来必须覆盖每笔记录和每张采用图片，不能只给路径或来源编号。后续哈希未变化时不再重复展示。

验收分为两部分：

1. **全量自动检查**：重新打开工作簿，一次遍历核对 Sheet 顺序、逐笔行数、每行 `图N` 锚点、嵌入实例数、图片 SHA256 映射、行列边界、数字精度和公式错误。
2. **有界视觉检查**：为每个 Sheet 生成覆盖全部实际数据行的紧凑联系预览；另检查首行、中间行、末行、图片最多行和布局变化边界。发现裁切、重叠、越界或布局变化时才全尺寸渲染受影响区块，禁止把 Sheet 数误当打印/PDF 页数，也禁止渲染大量空白格式行。

用户在一次展示后纠正任何业务内容时，只重建受影响交易及下游产物；未变化图片继续复用原视觉核验。
