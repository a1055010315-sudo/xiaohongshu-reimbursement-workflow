# 批次输出规则

## Manifest v3

`batch.mainPeriod` 是本期正常报销边界，不能用全部交易的最早日期反推。日期早于 `mainPeriod.start` 或显式标记为 `supplement` 的交易进入补报；补报必须写 `supplementReason`。

金额用最多三位小数的十进制定点字符串：

- `sourceAmount`：原始费用金额，也是总表支出金额。
- `reimbursementAmount`：本次实际报销；对公已付不实报必须为 `0`。
- 若兼容输入仍提供 `amount`，必须与 `sourceAmount` 完全相同，禁止取整或舍入。

使用中的材料必须声明 `usage`：

- `voucher`：逐笔凭证，可被多笔引用；工作簿只有一个媒体部件，可有多个锚点。
- `context`：上下文材料，无论被多少交易引用只展示一次。

`expected` 必须闭合：交易数、费用、实报、对公已付不实报、唯一图片哈希数、图片引用数。source scope 的每个单元必须唯一标记为 used 或 excluded。

## 补报名称

按补报人员在本批首次出现顺序汇总：

`（含<人员><期间>补报<笔数>笔<金额>元、<下一人员>...）`

日期使用 `YYYY.M.D`；单日只写一个日期，多日写开始和结束。无补报时不出现空括号。

括号必须同时出现在归档文件夹名、文字说明/明细/截图表文件名和明细标题。候选总表文件名不加括号。文字说明在对应人员合计后列出补报期间、笔数、金额和原因。

每位补报人员生成一张表：

- 多日：`<人员>_<开始日期>-<结束日期>_小红书补报明细.xlsx`
- 单日：`<人员>_<日期>_小红书补报明细.xlsx`

## 最终目录

```text
报销\
└─ <主期间>_<报销类别>（含...）\
   ├─ <主期间>_<报销类别>_报销文字说明（含...）.txt
   ├─ <主期间>_<报销类别>_本次报销明细（含...）.xlsx
   ├─ <主期间>_<报销类别>_报销明细对应截图表（含...）.xlsx
   ├─ <支出总表名>_截至<主期间结束日期>.xlsx
   ├─ <人员>_<补报期间>_小红书补报明细.xlsx
   └─ 报销截图\
      └─ <截图表类别>\
```

不要嵌套 profile 根目录。只归档成品和原始图片；Gate、manifest、预览、日志、模板与恢复文件只在系统临时目录存在。

图片文件名为 `序号_人员_事项_金额_日期`，冲突追加 8 位哈希。保留原字节和原 SHA256；不转码，不因 JPEG 缺少 FFD9 尾标记拒绝，尺寸从 SOF 读取。
