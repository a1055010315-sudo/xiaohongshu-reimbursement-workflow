# 工作簿规则

## 模板与成品交付表

明细、截图对应表、补报表和本批总表预览从 `assets/templates/xiaohongshu/` 的固定脱敏模板实例化。模板只提供标题、汇总区、表头、列宽和标准数据行样式；模板数据区不预置业务合并、历史颜色或历史行高。模板合并与成品合并是两个阶段。

文字说明从同目录的固定脱敏 `summary-text.txt` 模板投影。成品中的人员顺序必须与明细顺序一致；人员金额和实报合计使用 `reimbursementAmount`，对公已付不实报项使用 `sourceAmount` 且从实报合计排除。人员存在补报时，补报括号紧跟该人员金额；对公项排列在全部人员之后、实报合计之前。没有补报、对公项或无截图说明时，应删除相应整行占位符和空括号。模板中的字段提示、示例和填写规则只服务构建，不得出现在成品文字说明中。

成品按当前业务数据恢复上一期要求的人员分组、连续日期和费用组合合并；未使用空行不得生成合并。金额公式由明确的行号生成；禁止用模糊字符串插值生成范围。截图表每个唯一图片哈希只写一个 OOXML media part，多笔引用使用多个 anchor；`context` 只使用一个 anchor。无图交易必须显示“无图片凭证”。

金额样式按规范值的小数位选择 `0`、`0.0`、`0.00` 或 `0.000`；整数不得显示尾随小数点，一至三位小数不得补齐、截断或取整。每个成品使用的金额角色必须在模板 manifest 中完整声明四种样式，缺任一精度即阻塞，不得回退到基础样式。

“本次报销明细”固定为：第 3 行 `主期实报`、`补报（N笔）`、`实报合计` 三张卡片，第 4 行分别为主期实报、补报实报及两者相加的实报合计；第 5 行分别显示对公已付不实报与费用合计；第 6 行表头为“日期 / 支出明细 / 单笔金额 / 费用组合计 / 备注 / 分类 / 报销属性”。员工人员组 E 列标为“人员小计”，对公组标为“对公费用合计”。无补报时仍保留中间卡片并显示 0 笔、0 金额，副标题显示“无补报”，不得生成空括号。有补报时副标题必须包含与文件名括号一致的人员、期间、笔数和金额摘要。employee 的报销属性为“实报”，company 为“对公已付不实报”。标题行 32pt，第 2 至 4 行 15pt，第 5 行 24pt，表头 26pt，人员组 15pt，普通数据 24pt；明确超过列宽的长文数据行才用 42pt。末尾为 28pt 的 A:F 合并说明行，使用 Normal 样式，文案必须从当前主期笔数、补报人员/笔数与缺凭证事实动态生成，不得复制上一期姓名、金额或事实，不生成业务 footer。明细与截图表成品均必须显式设置 `showGridLines="0"`。

截图表模板的唯一空白标准数据行无填充且为 60pt；成品 A:E 按奇偶交易行恢复 `FFFFFCF4` / `FFFFF7E6`，F 及后续图区使用 `FFF5F8FA`。实际展示图片的行高 172.5pt，无 anchor 的行高 60pt。图片必须按 manifest 的 320×220 像素框执行 `contain` 等比缩放并居中，不得拉伸或越界。

补报表空白模板只含第 1 至 5 行。成品不得增加人员分组行，真实交易从第 5 行开始；连续日期及费用组合按数据动态合并。标题 34pt，副标题 28pt（长副标题 30pt），汇总和表头 24pt，普通数据 30pt，长文数据 38pt。交易后唯一 footer 为 28pt，A:B 合并显示“补报总计”，C:F 合并并以 `SUM(C5:C<最后交易行>)` 及正确缓存值显示费用总额；Sheet 名为“<人员>补报明细”。本批总表预览数据行固定 30pt。

## 候选总表局部补丁

全文件 SHA256 只是发布前的并发保护，不等于历史全表业务检查，也不得作为扩大解析范围的理由。

普通报销只允许：

1. 对正式总表全文件计算 SHA256，绑定并发基线。
2. 解析 workbook 关系以定位固定目标 Sheet；忽略未知扩展和 `mc:AlternateContent`。
3. 读取 A:F 表头，并在插入点前后固定 32 行内选择一整行白底、无业务合并、标准行高的数据样式；找不到时阻塞，不得扩大到全表搜索或按列拼接样式。
4. 当前期追加只定位现有业务尾部，不读取历史 B:F 业务内容；补报只流式建立 A 列日期索引和 D:F 合并边界，按日期插入且不能拆开既有 D:F 原子费用组。
5. 原行只做必要的坐标、局部公式和合并引用平移；G/H 等同行辅助内容随行保留。
6. 未涉及的 ZIP 部件按解压后字节逐一比较不变。

禁止解析历史人员、分类和总额，禁止要求第 2 行起连续，禁止重排历史记录，禁止因历史空行、辅助列、共享公式、WPS 元数据或旧格式失败。

独立 worker 从磁盘重读基线与候选，核对 local patch certificate 的文件和受管 part 绑定，并独立验证本批局部投影及受影响坐标后缀；不得再次解析历史 B:F 或完整机械重放整表补丁：

- 每个 manifest 交易恰好映射到一个本批行；
- 日期、事项、原始金额、人员、分类、公式、样式和行高正确；
- `projection.batchRows`、`batchRanges` 和批次金额闭合；
- 未涉及 OOXML 部件不变；
- 基线与候选 SHA256 和来源覆盖仍匹配。

## 本批预览

总表预览使用临时的“本批总表增量”投影工作簿，只含表头和本批行。不得渲染正式候选的 `A1:F<历史末行>`，也不得把独立 standalone PNG 或旧修订 PNG 当成当前门禁材料。

候选总表在归档中命名为 `<总表名>_截至<主期间结束日期>.xlsx`，正式总表仍是候选基线；`ledger-batch-preview.xlsx` 只用于本批增量预览，不替代正式历史区。

每个普通 Gate 预览任务必须绑定并核对工作簿 SHA256、Sheet、显式范围、候选 SHA256、计划 SHA256、来源覆盖、本批行区段和任务 binding digest。Gate 2 只有这些字段全部与 Gate 1 相同且源文件未变化时才可复用 Gate 1 PNG；任一字段缺失或不一致都必须阻塞，不能回退到候选全表、旧 PNG 或旧修订。

## 预览与媒体边界

预览请求必须声明当前候选 SHA、计划 SHA、来源覆盖和本批行区段；根表只渲染本批投影，不得渲染 `A1:F<历史末行>`。渲染失败只重跑受影响的预览任务，并复用同一 staging token 下已绑定且未变化的业务工件、候选和图片证据；连续失败必须阻塞 Gate，不得触发全流程重建或使用旧图替代。

图片类型按 magic bytes 和 JPEG SOF/PNG 头解析尺寸，并进行严格完整像素解码。原始媒体字节和原始 SHA256 必须原样进入归档，规范化的 `imageKind` 只用于内部布局。原图仅缺最后两个 `FFD9` 字节时，可在内存验证副本临时补尾后解码，归档字节不变；扫描数据、段结构或其他字节被截断时仍拒绝。文件超过 25 MiB、像素超过一亿、无法解析尺寸或无法严格解码也必须拒绝。

## Gate 2 工作簿全量对应

Gate 2 必须把每个 manifest 交易逐项对应到明细表、截图对应表、适用的补报表、文字说明和候选总表本批行，并核对日期、人员、事项、`sourceAmount`、`reimbursementAmount`、结算状态、分类、补报属性、公式与合并边界。候选核对只覆盖 `batchRows` 及局部坐标补丁，不得借 Gate 2 扩大到历史全表业务检查。

对应检查还必须覆盖每个唯一媒体和每个媒体引用；同源合并展示、`context` 只展示一次和无图交易都要分别证明“来源覆盖完整”与“成品显示规则正确”。按人员、分类、结算状态和补报人员汇总必须由逐项结果重新汇总，不能直接信任 Gate 1 合计。

Gate 2 为发现 Gate 1 内容错误而执行，不能退化为只比较 SHA256。独立复核不得进入 Gate 1 热路径；Gate 2 内文字说明、明细、截图表、各补报表和本批候选投影各解析一次，每个唯一媒体从原始路径 fresh-read/完整 decode 一次后复用于其全部引用，候选禁止读取 `batchRows` 之外的历史业务内容。

最终验收以只读安装版本 `0.5.0+codex.20260819174146` 为基线，不以人为构造的朴素实现替代。必须在同一机器、同一完全合成批次和相同冷/热规则下，分别测量旧版 `prepare + Gate 1 + finalize` 与新版 `prepare + Gate 1 + full-correspondence Gate 2 finalize` 的插件可控代码阶段中位总耗时；冷、热条件下新版都必须至少快 20%。外部人员或模型生成 `independent-evidence-review-v1` 的等待时间单独记录且不计入总耗时，插件读取 review、每个唯一媒体的 fresh-read/decode、审计和报告生成全部计入。基线安装缓存只读且禁止修改；不达标时必须先进行热点 review 并优化重复 I/O、解码或解析，不能减少复核范围。

具体输入独立性、报告字段、失效和展示规则见 [Gate 2 全量对应复核](gate2-full-correspondence.md)。
