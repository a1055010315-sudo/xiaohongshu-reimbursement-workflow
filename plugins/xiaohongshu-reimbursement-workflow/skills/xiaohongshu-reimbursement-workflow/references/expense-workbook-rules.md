# 工作簿规则

## 模板与成品交付表

明细、截图对应表、补报表和本批总表预览从 `assets/templates/xiaohongshu/` 的固定脱敏模板实例化。模板只提供标题、汇总区、表头、列宽和标准数据行样式；模板数据区不预置业务合并、历史颜色或历史行高。模板合并与成品合并是两个阶段。

成品按当前业务数据恢复上一期要求的人员分组、连续日期和费用组合合并；未使用空行不得生成合并。金额公式由明确的行号生成；禁止用模糊字符串插值生成范围。截图表每个唯一图片哈希只写一个 OOXML media part，多笔引用使用多个 anchor；`context` 只使用一个 anchor。无图交易必须显示“无图片凭证”。

## 候选总表局部补丁

普通报销只允许：

1. 对正式总表全文件计算 SHA256，绑定并发基线。
2. 解析 workbook 关系以定位固定目标 Sheet；忽略未知扩展和 `mc:AlternateContent`。
3. 读取 A:F 表头、A 列日期索引、D:F 合并边界和插入位置附近样式/行高。
4. 正常报销追加到现有记录末尾；补报按日期索引插入，不能拆开既有 D:F 原子费用组。
5. 原行只做必要的坐标、局部公式和合并引用平移；G/H 等同行辅助内容随行保留。
6. 未涉及的 ZIP 部件按解压后字节逐一比较不变。

禁止解析历史人员、分类和总额，禁止要求第 2 行起连续，禁止重排历史记录，禁止因历史空行、辅助列、共享公式、WPS 元数据或旧格式失败。

独立 worker 从磁盘重读基线与候选，重新机械生成本批补丁并比较：

- 每个 manifest 交易恰好映射到一个本批行；
- 日期、事项、原始金额、人员、分类、公式、样式和行高正确；
- `projection.batchRows`、`batchRanges` 和批次金额闭合；
- 未涉及 OOXML 部件不变；
- 基线与候选 SHA256 和来源覆盖仍匹配。

## 本批预览

总表预览使用临时的“本批总表增量”投影工作簿，只含表头和本批行。不得渲染正式候选的 `A1:F<历史末行>`，也不得把独立 standalone PNG 或旧修订 PNG 当成当前门禁材料。

候选总表在归档中命名为 `<总表名>_截至<主期间结束日期>.xlsx`，正式总表仍是候选基线；`ledger-batch-preview.xlsx` 只用于本批增量预览，不替代正式历史区。

## 预览与媒体边界

预览请求必须声明当前候选 SHA、计划 SHA、来源覆盖和本批行区段；根表只渲染本批投影，不得渲染 `A1:F<历史末行>`。渲染失败只重跑渲染，不重建业务事实或图片证据。

图片类型按 magic bytes 和 JPEG SOF/PNG 头解析尺寸，原始字节和 SHA256 必须保留。可正常解码但缺少标准 JPEG `FFD9` 尾标的原图允许进入归档；只有无法解码、无法解析尺寸或字节损坏时拒绝。
