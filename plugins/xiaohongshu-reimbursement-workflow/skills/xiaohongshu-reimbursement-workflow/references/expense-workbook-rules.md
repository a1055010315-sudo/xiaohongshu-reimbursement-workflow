# Excel 整理与验收规则

本页是统一报销工作流的内部规则。只在处理小红书、公司或驻所的本次明细、候选、结构修复或发布核验时完整读取；profile 身份以 `ledger-profiles.json` 为准，格式以 `workbook-style-contract.json` 为准。

## 目录

1. 范围与边界
2. 只读预检与行类型
3. 合并单元格有效值
4. 阻塞项与确认
5. 日期解析
6. 备注规范化
7. 排序、费用组与合计
8. 样式与工具
9. 重新打开验收

## 1. 范围与边界

- 只处理父级 `affectedProfiles` 绑定的精确工作簿、唯一可编辑工作表、记录集和日期范围，不扩大范围。
- 永不直接编辑根目录总表或用户原件；编辑前后比较源文件 SHA256，所有修改只发生在父级专用临时副本。
- `current-detail`（本次明细）默认 A-F 为：日期、项目或费用明细、单笔金额、费用组合计、备注/分类、报销属性；人员由连续区块标题表达。
- `ledger-candidate/root`（候选/根表）A-F 固定为：日期、项目或费用明细、单笔金额、费用组合计、支出人/主体、备注/分类。
- 文件名、目标 Sheet 名及 A-F 表头指纹必须同时匹配 profile。缺少 D 列、插入未知列、表头移动或目标 Sheet 歧义均为 `STRUCTURE_DRIFT`，在处理该 profile 的证据前阻塞，禁止静默套列。
- 不编造或擅自改变日期、项目、金额、支出人、备注和业务含义。
- 金额使用有符号十进制定点值重算并保留用户确认的原始精度，最多三位小数；不得用二进制浮点直接汇总，也不得把三位小数静默舍入到分。读取 XLSX 公式缓存时，仅当有限数值与最近千分位的差不超过 `1e-9` 才把浮点噪声规范化到该千分位；真正超过三位小数的值仍阻塞。
- 保存、导出或重新打开失败时停止，不交付未验收文件。

## 2. 只读预检与行类型

首次写入、读取微信前，对每个受影响 profile 一次性读取并记录：源路径/SHA256、工作表集合、目标/保护 Sheet、A-F 表头指纹、已用范围、隐藏行列、公式、合并范围、非空行、数字格式、行列尺寸、冻结窗格、打印设置和关键样式角色。以“源 SHA256 + profile 配置摘要 + 样式契约摘要 + 预检器版本”为缓存键；未变化时复用。

按契约分类漂移：

- `STYLE_DRIFT`：字体、填充、边框或角色颜色异常；根表不动，先生成修复候选；
- `LAYOUT_DRIFT`：列宽、行高、对齐、合并拓扑或打印设置异常；阻止发布并生成修复候选；
- `STRUCTURE_DRIFT`：缺列、插列、表头错位、目标 Sheet 缺失/歧义；立即停止该 profile，不允许猜测。

未知 Sheet 默认保护。候选前记录所有保护 Sheet 的值、公式、样式、合并、行列尺寸、关系和相关 OOXML part 摘要；重新打开验收时差异必须为零。

逐行区分：

- 明细行：有项目或单笔金额，代表一笔费用；
- 费用组续行：有项目或金额，但 D/E/F 因合并没有独立值；
- 人员/对公区块标题行：显示人员或主体、笔数和小计，属于 `current-detail` 展示结构，不代表费用；
- 表头或说明行：有文字但不代表费用；
- 完全空白行：A-F 全空。

只有父级范围内且明确允许移除的完全空白行可以删除。表头、说明行和无法分类的非空行不得删除。按日期范围处理时先建立候选记录集；空日期行只有在同一连续费用组、同一合并范围或紧邻上下文能够证明时才可归入，不能用远处最近的上方日期推断。记录所有离散区块和源行号。

## 3. 合并单元格有效值

- 读取前记录全部合并范围及左上角值。
- 在基线、候选或明细中，D/E/F 位于合并区域时，使用所属合并范围左上角的有效值；子单元格为空不是缺失。区块标题和分隔行不得继承成业务值。
- 解除旧合并前，把每行所需有效值、原值、公式、逐格 computed style、行高和原合并信息保存在内存记录中。
- 创建或重建合并范围前，先显式清空除左上角锚点以外所有子单元格的值、公式和富文本；工具界面显示为空不能证明 OOXML 中没有隐藏内容。
- C 列单笔金额通常不依赖合并；明细行 C 为空且不能证明是非明细行时必须阻塞。
- A、B、C 的真实缺失或冲突是阻塞项；由合并造成的 D/E/F 空值不是。

## 4. 阻塞项与确认

以下情况停止写入并一次性编号询问：日期有多个解释；有项目但金额缺失；金额与合计、公式或凭证冲突；支出人/备注无法确定并影响费用组；行类型、范围或工作表矛盾；存在公式错误；保存或重新打开不可靠。

每个问题给出精确工作表、源行号、A-F 当前值、合并范围、歧义和不同处理的影响。需要用户看原表时，每个独立问题单独提供保留工作表名、行号和 A-F 上下文的原表裁剪图；中文或路径出现乱码时先修复呈现。用户要求逐一核对时，任何改变 A-F 业务值的回填、继承、规范化或文本修正都逐项确认。未确认项不得被排序、合并或公式重建掩盖。

## 5. 日期解析

按顺序识别 Excel 日期/日期时间、合法 Excel 日期序列、明确文本日期、年份可由批次唯一确定的 `m.d` 文本、日期范围文本。保存原始类型、值和数字格式。

- General/普通数字格式下数值 `6.2` 默认是 6 月 2 日，不是 6 月 20 日；文本 `6.20` 才保留为 6 月 20 日。
- `6.1` 等无法由类型、格式、相邻记录和批次范围唯一解释的值必须询问。
- 含字母等异常日期文本不得凭常识修正。
- 单日期保存为真实 Excel 日期/数值并显示 `m.dd`；若末尾零丢失则使用 `m"."dd` 并重新打开验证。
- 日期范围保留原文本，以起始日期排序，不强行拆行。
- 只有用户明确授权按相邻日期补齐时才回填，并记录每行前后值。

## 6. 备注规范化

只执行以下精确映射，未知备注保持原样；只可清除首尾空格：

| 原备注 | 统一备注 |
|---|---|
| `AnnaW`、`annaw`、`杭州AnnaW`、`杭州annaw`、`萧山AnnaW单` | `杭州annaw` |
| `萧山竞业`、`萧山竞业；`、`萧山竞业单` | `萧山竞业单` |
| `贾佳`、`贾佳单` | `贾佳单` |

项目或费用文字明确写出某个具体单子、项目或业务名称时，备注/分类使用该名称，不得降级成泛化的 `日常报销`。例如 `上海竞业2` 的差旅、U盘和快递均归为 `上海竞业2`，写明 `佛山嘻箱记` 的返佣归为 `佛山嘻箱记`。只截取材料中能够唯一确定的稳定名称，不把“预支”“差旅”“快递”“返佣”等费用动作并入单子名称；出现多个候选名称、简称映射不清或用户另有指定分类时先询问。

记录每次实际映射。规范化只影响备注及费用组边界，不改变金额、日期、项目或支出人。

## 7. 排序、费用组与合计

把目标记录保存为含 manifest v3 稳定来源顺序、profile、源行号、A-F 原值/公式、合并有效值、行类型、日期键、回填状态、备注前后值、逐格 computed style、行高和原合并信息的逐行记录。排序前后明细数、项目数和金额数必须一致。随后按产物类型使用三个布局模式；不要把这里的“布局模式”与账本 profile 混为一谈：

### `current-detail-person-grouped`

- 只保留当前账本 profile 的交易。普通实报按人员建立连续区块；新任务使用最小 `sourceOrder` 决定人员区块和同日稳定顺序，旧 manifest 只读恢复时才兼容数组顺序。
- `对公已付不实报` 不混入人员区块，按主体/汇总标签建立区块并统一置于最后；同一人员同时存在实报和对公记录时也必须拆开。
- 人员标题、对公标题、表头、说明和空白分隔行均是展示行。标题中的笔数和小计必须由本区明细范围确定，但标题行不计入业务多重集合或候选输入。
- 顶部标题/副标题带、人员标题、对公标题和顶部汇总卡属于“标签型合并区”：完成全部合并后，必须对每个合并范围的左上角锚点显式设置水平 `center`、垂直 `middle`。表尾说明、业务备注等“叙述型合并区”保持水平 `left`、垂直 `middle` 并换行；普通业务文本单元格不得因修复合并区而被整区居中。
- 同一区块内，相邻且“正式人员/主体 + 精确 classification + 明细类型 + settlement”均非空且完全相同的明细属于同一费用组；日期变化本身不拆组。多行组的 D/E/F 必须使用完全相同的纵向合并范围，D 锚点写 `=SUM(C起始行:C结束行)`，E/F 值只在锚点；单行组不合并。A 可按连续相同已确认日期独立合并。
- 全表不要求日期非递减，只要求每个区块内日期非递减。合并不得跨人员/主体、classification、明细类型、settlement、表头、说明或分页线。

### `ledger-candidate/root`

- 从基线和 manifest 中当前账本 profile 的交易直接构建，不从 `current-detail` 的可见行导入。按日期键稳定升序，同日保持源顺序。
- 重建费用组前先解除目标区旧合并。相邻明细只有在正式支出人/主体、精确 `classification`、明细行类型和独立 `settlement` 均非空且完全相同时才属于同组；日期变化本身不拆组。`classification`、人员、类型或 `settlement` 任一变化都拆组；任一组键为空时该交易为单行组。组不能跨越空白行、表头或说明行。
- 多行组：D/E/F 只合并该连续组；D 左上角公式为 `=SUM(C起始行:C结束行)`；E/F 值放左上角。
- 单行组：D 保留直接金额或原表单行合计形式；E/F 不与邻组合并。
- A 只在连续且同一已确认日期的明细行间合并，不能跨日期。
- D/E/F 锚点显式设为水平 `center`、垂直 `middle`、自动换行、`shrinkToFit=false`；根据文字和列宽显式设置组内行高。超过 7 行或 210pt 的合并块生成专项预览和警告，但不自动拆分。

### `ledger-reorder-correction`

- 只移动用户确认范围内已经存在的业务记录，不新增、删除、去重或改写任何业务字段。v2 plan 用合并连通关系把一行或多行识别为 `contiguous-row-block`；完整位于一个逻辑记录内的横向/竖向合并、各物理行高和逐格样式随整个块移动。跨逻辑记录、跨物理范围或无法装入保留行带的块必须阻塞。候选与基线的规范化业务多重集合、逻辑记录数、物理记录行数和十进制定点金额合计必须完全相等，`expectedAmountDelta` 必须严格为 `0`。
- 使用“规范化日期键 + 基线顺序号”做稳定排序；同一日期键保持基线顺序。范围外所有单元格值/公式、逐格 computed style、行高、列宽、合并范围和工作表结构保持不变。
- 每条记录必须携带源值与公式、公式缓存、目标列内每个单元格的 computed style、每个源物理行高及二维合并元数据。行高和样式随记录块迁移，不得留在原物理行；移动公式必须能按相对位置安全迁移。公式解析必须覆盖 Unicode/带引号工作表名、整行、整列、定义名称及传递引用，并扫描其他工作表的条件格式/数据验证以及 chart、table、pivot 等 OOXML part 中的非单元格公式；外部/3D、未完整解析、跨逻辑记录、绝对行、动态 `OFFSET`/`INDIRECT` 或其他位置/间接/易变语义必须 fail-closed。任何定义名称直接或传递触及移动记录时，即使没有普通单元格公式消费者也阻塞；仅可豁免已证明只描述打印布局的 `_xlnm.Print_Area`/`_xlnm.Print_Titles`。纯顺序无关聚合的参数只能是以逗号或分号分隔的 A1 引用/范围，且必须完整覆盖可移动行、每格只计一次；包含乘除、数组表达式或其他运算的 `SUM/AVERAGE/MIN/MAX` 不得豁免。工作簿声明 R1C1 引用模式时，A1 审计器不得继续执行重排。
- 如果改变目标物理行高会影响重排列以外的任何单元格或合并，必须阻塞。移动源行/目标行上的 native hyperlink（即使位于重排列外）以及任意工作表中指向移动行的内部 hyperlink 都必须阻塞或由专门实现迁移；不得让凭证链接留在物理位置。目标 Sheet 出现 PivotTable、table、validation、conditional formatting、drawing、control/OLE、cell watch、smart tag 或不透明 extension metadata 时一律 `unsupported`；可移动单元格带 `cm`、`vm`、`ph` 或其他未证明可迁移的语义属性，以及工作簿带坐标型 `calcChain` 时同样阻塞。每个 OOXML row/cell 必须有显式 `r` 坐标；范围外 cell/formula 语义属性必须逐坐标保持，可移动公式除无属性或 `t="normal"` 外均阻塞。除逐格业务/样式检查外，还要核对工作簿日期系统、工作表非单元格结构、消费者 `r:id` 到 relationship target 的语义映射和所有未授权 OOXML parts 的 SHA256；只比较 target 集合而丢弃 rId 不算等价，无法证明结构等价就不能发布。
- `copyFrom("all")` 只能作为搬运优化，不能作为格式迁移成功的证据。必须在重新打开后逐格比较 computed style、逐行比较行高、逐范围比较合并关系。
- 重建合并前清空所有非锚点子格。验收时同时检查工作表 OOXML 中合并子格没有值/公式/内联字符串，并在独立验收副本解除合并后确认这些子格仍为空；不得为验证而改动正式候选。

三个 profile 的 C 都必须是明确数值；金额未确认时不得生成合计公式。

## 8. 样式与工具

- 使用可用 spreadsheet 能力和其规定的工具；以 `workbook-style-contract.json` 为机器可读权威。三类支出表继承小红书语义版式；公司和驻所只允许契约声明的蓝色角色覆盖，其他角色不得自行变色。
- 清理重排区优先只清内容，禁止无要求清除格式或整表重做样式。
- 重排记录时，以源记录逐格 computed style 为权威，显式重放字体、填充、边框、对齐、换行和数字格式，并显式设置源行高；目标物理行原有格式不得作为结果依据。
- 字体使用工具支持的字段，例如 `setFont({name:"仿宋", size:14})`；不要使用不受支持的 `typeface`/`fontSize` 写入字段。
- 日期和金额只设置必要数字格式。每笔 C 独立执行：整数显示 0 位；非整数且用户原值明确为三位小数时显示 3 位；其余非整数显示 2 位。D 及相关合计使用组内最大显示精度，不能因为区内存在一笔三位小数就把整段统一设为三位。重新打开核验原值、尾零显示和公式结果没有丢失精度。不新增无要求的边框、填充、颜色、调试列、辅助表或隐藏内容。
- `current-detail-person-grouped` 使用当前 profile 主题：小红书为绿色基础，公司/驻所为蓝色角色覆盖；只有 `对公已付不实报` 使用浅橙提示色。候选/根表继承相同语义角色，但不得导入人员标题或空白展示行。
- 插入或扩展人员区块时，禁止把原对公标题、区块末行或表尾说明行直接复用为业务行。新增中间行复制已批准的同类“区块内部业务行”完整样式；只有实际最后一条业务行使用区块底边框。扩展结束后按区块类型重新应用标题色和上下边框，并确认说明行文字及样式仍完整存在。
- 用户要求全部居中时，完成全部合并后再对目标 A:F 非空区统一设置水平 `center`、垂直 `middle`，并检查合并区域左上角。
- 构建/导出、重新打开语义校验和渲染视觉校验使用独立进程；渲染范围只覆盖实际数据区或代表性区块。
- 同一主要阶段可以在一个进程内批量处理多个工作簿，但每个工作簿只导入、保存或重新打开一次。不要为单个 Sheet、图片或检查项重启进程。
- 不在最终工作簿增加 manifest、审计、调试或缓存用的隐藏工作表；这些状态只进入父级任务临时目录。

## 9. 重新打开验收

每个新的工作簿字节版本关闭并重新导入一次；全部满足后生成绑定“工作簿 SHA256 + 依赖 manifest 摘要 + 本规则版本 + 验收器版本”的验收证书。缓存键未变化时直接复用，只有依赖变化才重新执行本节：

1. 源文件 SHA256 前后相同；工作表数量、名称、目标范围符合 profile，所有保护 Sheet 和未授权 OOXML 差异为零。
2. 排除标题、表头、说明和空白分隔行后，每笔日期、项目、金额、人员/报销属性和备注可追溯；规范化业务多重集合与该 profile 的 manifest 投影完全相等，每笔本 profile 交易恰好一次、其他 profile 交易为零。
3. `current-detail` 每个区块内日期非递减、人员区块顺序和对公末尾顺序正确；候选/根表全局日期非递减。单日期仍是日期/数值且 `6.10`、`6.20`、`6.30`、`7.10`、`7.30` 等显示不丢零。
4. 每个费用组 D 公式范围精确覆盖本组 C，区块小计和顶部 `实报合计`、`对公已付不实报`、`费用合计` 由正确范围计算；按“整数 0 位、普通非整数 2 位、明确三位小数 3 位”的逐笔规则，用十进制定点值独立重算并与公式一致。
5. `current-detail` 与候选/根表的 D/E/F 必须使用同一个费用组范围，只覆盖同正式支出人/主体、同精确 `classification`、同明细类型、同 `settlement` 的连续明细；A 只按连续相同日期独立合并。每个 D/E/F 锚点居中、垂直居中、换行、不缩小字体，行高显式且显示完整。
6. 全表扫描无 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`。
7. 全量检查契约角色的字体、字号、填充、边框、数字格式、对齐、换行、列宽、行高、冻结窗格和打印设置。枚举全部合并范围，标签型及 D/E/F 锚点居中，叙述型左对齐；`mergedAnchorAlignmentMismatchCount`、裁切计数和样式漂移计数必须为零。重排分支仍须覆盖重排区全部单元格。
8. `ledger-reorder-correction` 的范围外值/公式、computed style、行高、列宽、合并和工作表结构差异必须为零；范围内稳定排序、多重集合相等、记录数相等和 Decimal 金额增量 `0` 必须分别给出机器验收结果。
9. 全量扫描每个合并范围的非锚点子格；OOXML 内容残留数和独立副本解除合并后的非空子格数必须为零。D/E/F 范围不一致、公式空白、`####`、裁切、边框断裂或无解释样式混用均阻塞。
10. 对普通明细/候选表渲染每个修改区块；对重排修正生成覆盖整个重排区的分段预览，包含首行、末行、每个格式变化边界及尾零日期；对图片表用覆盖全部实际数据行的紧凑联系预览加代表性布局区块，确认无裁切、日期隐藏、重叠或破损。不要把 Sheet 数解释为打印页/PDF 页数。
