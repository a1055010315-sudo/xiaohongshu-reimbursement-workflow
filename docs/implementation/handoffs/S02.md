## Review-bound 与限制

- 正式归档字节不能独立推出 `batchId`；无图片交易也不能从 screenshot anchor 推出 transaction ID。两者保留 `sourceReview` authority，并在 `reviewBoundFacts` 明示。
- summary 批注、对公 summary label 的精确分组不在 v2 review 交易形状中；模块只证明可从文件闭合的金额/结构，不伪造额外语义。
- 补报原因能从正式补报表/summary 读取，但 v2 review 没有对应字段，因此标为 `published_archive_file_only`，不声称被 review 交叉证明。
- 普通生成明细的 C 列是 `sourceAmount`，不是独立的逐笔 `reimbursementAmount`。逐笔差额分配只能由 task-internal review 提供；正式文件独立证明范围止于 detail row 的日期/人员/来源事实以及 summary 的逐人/全局实报总额，因此输出必须保持 review-bound，不能声称 file-parsed。
- 普通 manifest attestation 中未注册且不属于 published archive input 的历史 baseline/raw material 只参与 JSON 声明和业务结构审计，不读取其路径。只有与本 source 显式发布材料相交的条目才做 path/SHA/声明 kind 映射；coverage 不完整时不得宣称全路径已验证。
